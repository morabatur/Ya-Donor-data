# Дані для додатку ЯДонор

Цей репозиторій нічого не робить сам по собі: він лише готує файли,
які читає мобільний додаток [ЯДонор](https://github.com/iyzhegulovych-swag/Ya-Donor).

Код додатку лежить окремо і може бути приватним. Публічним має бути
саме цей репозиторій, інакше телефон не зможе завантажити файли.

## Що тут лежить

| Файл | Що це |
| --- | --- |
| `fetch_blood_needs.py` | збирає потребу у крові з donor.utcc.gov.ua |
| `utcc_mapping.json` | зіставлення назв центрів на сайті з id у довіднику додатку |
| `articles.json` | пам'ятка донора: статті, які показує додаток |
| `donor-days.json` | розклад днів донора та виїзних акцій |

## Як це працює

Щодня о 5:00 UTC дія GitHub Actions запускає скрипт і кладе три файли
у гілку `data`. Додаток читає їх за адресами:

```
https://raw.githubusercontent.com/morabatur/Ya-Donor-data/data/needs.json
https://raw.githubusercontent.com/morabatur/Ya-Donor-data/data/articles.json
https://raw.githubusercontent.com/morabatur/Ya-Donor-data/data/donor-days.json
```

Якщо мережі немає або щось зламалося, додаток показує копії, вшиті у
збірку. Нічого не падає, просто дані будуть старішими.

Запустити збір вручну: вкладка **Actions** → **Оновити дані додатку** →
**Run workflow**.

## Як відредагувати статтю

Правиться `articles.json` у цьому репозиторії. Наступного ранку
виправлення доїде до всіх, хто вже має додаток, без нового релізу.

Формат простий:

```json
{
  "id": "коротке-ім'я-латиною",
  "title": "Заголовок",
  "summary": "Один рядок під заголовком",
  "sections": [
    { "body": ["Абзац без підзаголовка."] },
    { "heading": "Підзаголовок", "body": ["Абзац.", "Ще абзац."] }
  ]
}
```

Не забудь підняти `updatedAt` на сьогоднішню дату: саме по ній додаток
розуміє, що файл новіший за той, який у нього вже є. Це стосується і
`articles.json`, і `donor-days.json`.

Копію `articles.json` варто час від часу переносити й у сам додаток
(`shared/src/commonMain/composeResources/files/`), щоб ті, хто щойно
встановив його, одразу бачили свіжі тексти.

## Як додати день донора

Правиться `donor-days.json`. Додаток перевіряє цей файл раз на добу і
показує лише майбутні дати — минулі можна не видаляти, вони просто
зникнуть зі списку.

```json
{
  "id": "lviv-1-2026-12-05",
  "title": "День донора у центрі крові",
  "date": "2026-12-05",
  "centerId": "lviv-1",
  "timeFrom": "09:00",
  "timeTo": "14:00",
  "details": "Візьміть паспорт. Попередньо поїжте.",
  "url": "https://example.org/announcement"
}
```

| Поле | Обов'язкове | Що це |
| --- | --- | --- |
| `id` | так | унікальний ключ, зручно робити з id центру й дати |
| `title` | так | заголовок, який побачить людина |
| `date` | так | тільки формат `2026-12-05` |
| `centerId` | або це, або `place` | id центру з довідника додатку — тоді день донора видно і на картці центру |
| `place` | або це, або `centerId` | адреса виїзної акції, якої немає в довіднику |
| `timeFrom`, `timeTo` | ні | години прийому |
| `details` | ні | що треба знати перед візитом |
| `url` | ні | посилання на оголошення |

Id центрів беруться з довідника додатку —
`shared/src/commonMain/kotlin/com/example/manq/data/BloodCentersDb.kt`.
Перевірка в Actions стежить за форматом дати, унікальністю `id` та тим,
що місце взагалі вказане, але сам довідник їй недоступний: якщо
`centerId` помилковий, день донора просто не з'явиться на картці центру.
Тому надійніше — скопіювати id з файла довідника, а не набирати руками.

Усесвітній день донора (14 червня) сюди вписувати не треба: постійні
дати лежать у коді додатку й показуються щороку самі.

## Перевірити скрипт локально

```bash
python3 fetch_blood_needs.py            # таблиця в консоль
python3 fetch_blood_needs.py --high     # тільки висока потреба
python3 fetch_blood_needs.py --app -o needs.json
```

Залежностей немає, потрібен лише Python 3.
